# Architecture

Owner: **LEAD**. Changes only via the lead (see `docs/process/communication.md`).
Every decision here is mirrored by a dated entry in `docs/decisions.md`.

## 1. Engine and languages

| Item | Decision |
|---|---|
| Engine | **Godot 4.7.2-stable** (pinned; `tools/setup/godot_version.txt`). Upgrades are a lead decision. |
| Renderer | Forward+ (Vulkan). Headless CI uses `--headless` (dummy renderer). |
| Physics | Jolt (Godot built-in 3D physics engine setting `physics/3d/physics_engine="Jolt Physics"`). |
| Primary language | **GDScript, statically typed** (`var x: int`, typed arrays, `-> void`). Untyped declarations are a lint failure (`untyped_declaration` warning = error in `project.godot`). |
| C# / GDExtension | **Not allowed** without a decision-log entry stating the measured bottleneck. Candidate later: detection/visibility raycasts batched in a GDExtension if profiling shows > 2 ms/frame server-side with 30+ observers. |
| Third-party code | Allowed (addons, Python libs, Blender). Must be vendored under `game/addons/<name>/` or pinned in `tools/requirements.txt`, with licence noted in `docs/third_party.md`. **No third-party art/audio assets of any kind.** |
| Tooling | Python 3.11+ (`tools/`), Blender **4.5 LTS** (headless, `blender -b --python`), gdtoolkit (`gdlint`, `gdformat`). |

## 3. Process model: authority and networking

**Server-authoritative from day one. Solo = local host.**

* All gameplay state lives on the **authority** (the host peer, id 1). Clients send *intents*
  (input, interaction requests, hit claims); the authority validates and applies, then
  replicates results.
* **Solo play uses `OfflineMultiplayerPeer`** (Godot default), on which `multiplayer.is_server()`
  is `true` and `call_local` RPCs run locally. Therefore solo exercises the exact same code path
  as a host. AI teammates fill empty crew slots on the host in both solo and co-op.
* Co-op uses `ENetMultiplayerPeer` (max 4 players). Lobby/session code lives in `game/core/net.gd`
  (LEAD API, ENV A implements gameplay replication).
* Rule: **No system may assume a single player.** Never use "the player"; always iterate
  `Net.players()` / crew members. Never read `Input` outside the local player's input component.
  Every gameplay RPC is declared with explicit `@rpc` mode and validated on the server.
* Latency model (co-op PvE, cheating not a threat model):
  * Own movement: client-predicted, client-authoritative position sent at 30 Hz,
    server sanity-checks speed/teleport.
  * Own shooting: client performs hitscan for feel, sends a *hit claim*
    (target id, hit zone, distance, weapon id, shot seq); server validates
    (rate of fire, ammo, LOS raycast, max range) and applies damage.
  * Everything else (AI, detection, pagers, interactions, loot, director, doors, drills) is
    computed **only on the server**; clients render replicated state.
* Replication tools: `MultiplayerSpawner` for dynamic entities (NPCs, bags, deployables),
  `MultiplayerSynchronizer` for continuous state (transforms, meters), reliable RPCs for
  discrete events. Every networked entity carries a stable `net_id: int` assigned by
  `Ids.next()` on the server.
* Helper: `Net.is_authority() -> bool` (== `multiplayer.is_server()`). Gameplay code guards
  state mutation with it.

## 4. Autoloads (game/core, LEAD API)

| Autoload | Purpose |
|---|---|
| `Log` | Leveled logging with channel tags (`Log.info(&"stealth", "...")`). Headless tests capture it. |
| `EventBus` | Typed global signals for cross-system *facts* (see §5 and `docs/contracts/events.md`). |
| `Net` | Peer/session management, player registry, authority helpers, RPC relay for EventBus replication. |
| `GameRng` | Seeded, named random streams per run (see §7). |
| `Ids` | Server-assigned stable `net_id`s; lookup of nodes by id. |
| `Modifiers` | Skill/perk/asset modifier query service (see `docs/contracts/modifiers.md`). API by LEAD; values populated by ENV B's progression code; queried by ENV A systems. |

Autoloads are thin. Gameplay managers (StealthDirector, AssaultDirector, LootManager, ...) are
**nodes inside the heist scene tree** (under `HeistRuntime`), not autoloads, so a heist reset is
a scene reload with no lingering state.

## 5. Event bus rules

* `EventBus` signals are **facts that already happened** ("pager_answered"), never commands.
  Commands are direct method calls on the owning system, obtained through groups or the
  `HeistRuntime` service locator (`HeistRuntime.get_service(&"stealth")`).
* Gameplay facts are emitted **on the server** by the owning system. Facts that clients need
  (UI, audio, voice lines) are relayed with `Net.replicate_event(signal_name, args)` which
  re-emits them on clients. Args must be network-serializable (ints, StringNames, Vector3,
  Dictionaries of those; nodes are passed as `net_id`).
* A signal's signature changes only by contract update.
* Listeners must not assume ordering between listeners.

## 6. Scene and composition conventions

* One scene per entity type; behaviour by **composition of child components**
  (`HealthComponent`, `InteractableComponent`, `DetectableComponent`, `NetSync`...).
  Inheritance depth max 2 below a Godot built-in.
* **Gameplay prefab + visual slot pattern** (cross-env seam): ENV A authors logic prefabs
  (door, safe, camera, keycard reader, loot spawn, escape zone, guard, civilian...) whose
  visuals live in an exported `visual_scene: PackedScene` instantiated under a `Visual` node.
  ENV C supplies visual scenes that satisfy `docs/contracts/visual_slots.md` (pivot, size,
  named attachment markers). ENV A ships placeholder visuals so it never blocks on art.
* Heist maps are authored by ENV C and expose gameplay structure through **contract nodes**
  defined in `game/contracts/map/` (see `docs/contracts/heist_map.md`).
* Data is **data**: weapons, mods, skills, perks, deployables, difficulty tables, enemy stat
  tables, heist variant tables are `Resource` files (`.tres`) whose schema scripts live in
  `game/contracts/data/`. No balance numbers in code; code reads tweak resources.
* Groups are named in `snake_case` and listed in `docs/contracts/groups.md`; string literals for
  groups/ids are referenced through constants in `game/contracts/ids.gd`.

## 7. Randomization

* At heist start the server chooses `run_seed: int` (or uses a forced seed in tests / replays),
  replicates it, and calls `GameRng.begin_run(run_seed)`.
* Systems request **named streams**: `GameRng.stream(&"patrols")`. Each stream is an independent
  `RandomNumberGenerator` seeded from `hash([run_seed, stream_name])`, so adding a roll in one
  system never shifts another system's results. All per-run variation must go through
  `GameRng`; `randi()`/`randf()` are banned in gameplay code (lint rule in `check_all.sh`).
* Dynamic heist variables are resolved once, on the server, by ENV A's `VariantResolver` from
  ENV C's `HeistVariantTable` resource, before NPCs spawn; the resolved result is a plain
  Dictionary replicated to clients and logged (for bug repro: seed + resolved table).

## 8. Naming conventions

| Thing | Convention | Example |
|---|---|---|
| Files, folders | `snake_case` | `pager_system.gd`, `guard_ai.tscn` |
| `class_name` | `PascalCase`, globally unique | `PagerSystem` |
| Constants / enums | `UPPER_SNAKE` / `PascalCase` enum, `UPPER_SNAKE` members | `enum AlertState { CALM, SUSPICIOUS, ALERTED }` |
| Ids (data, cues, voice lines) | `StringName`, `domain.snake_name` | `&"weapon.kestrel_p9"`, `&"cue.pager_beep"` |
| Signals | past-tense verb phrase | `pager_answered` |
| Private members | leading underscore | `_timer` |
| Heist ids | `snake_case` short | `glasshouse` |
| Generated assets | `<category>_<name>[_<variant>]` + suffix per style guide | `prop_desk_office_a.glb` |

**StringName ordering:** `<` on StringName compares interned pointers, not text. Never `sort()` an array
of StringNames (or use them as ordered keys) when the order matters; use
`sort_custom(func(a, b): return String(a) < String(b))`.

Units: **meters, seconds, kilograms, degrees in data / radians in code**. +Y up, −Z forward
(Godot default). Money in integer cents is unnecessary; use integer dollars.

## 9. Testing and CI

* Test runner: `game/tests/framework/` (lightweight, no dependency). Tests are scripts named
  `test_*.gd` extending `TestCase` with `func test_*() -> void` methods; `await` allowed.
  Run all: `tools/ci/run_tests.sh` (or `run_tests.sh a` for one env's folder).
* `tools/ci/check_all.sh` = import project headless → gdlint → banned-API grep → ownership check
  (on env branches) → unit tests → integration tests → `validate_level` for every heist.
* GitHub Actions (`.github/workflows/ci.yml`) runs `check_all.sh` on every push.
* Every phase has a **gate integration test** in `game/tests/integration/` written by the lead
  (see `docs/roadmap.md`). A phase is complete only when its gate passes on trunk.
* Headless simulation: systems must run with `--headless`. Anything visual-only (shaders,
  post FX) is optional at runtime when `DisplayServer.get_name() == "headless"`.
* Tests that write to `user://` must use a per-process root (e.g. `user://test_<pid>/`), because every checkout
  shares one `user://` and parallel runs collide (ENV B finding, D-039).
* Bots: integration tests drive crew members through `CrewInput` intents (the same intent API
  used by players and AI teammates), never by poking internal state.

## 10. Performance budgets (target: 60 fps @ 1080p mid-range GPU, 4 players, 60 NPCs)

| Budget | Value |
|---|---|
| Server AI tick | detection at 10 Hz staggered; behaviour at 5–10 Hz; ≤ 4 ms/frame total |
| Draw calls per view | ≤ 2,500 |
| Active lights casting shadows | ≤ 8 in view |
| NPCs alive | ≤ 60 enemies (difficulty-capped), ≤ 30 civilians |
| Texture memory per heist | ≤ 1.5 GB |
| Net | ≤ 64 kbps per client steady-state |

## 11. Save data

`user://` only. ENV B owns `SaveService` (versioned JSON, migration functions per version).
Progression is per-profile and local; host does not own clients' progression. Clients send
their resolved loadout/skills/perk summary at heist join; host validates basic legality
(point totals) and uses it for modifier queries for that peer.
