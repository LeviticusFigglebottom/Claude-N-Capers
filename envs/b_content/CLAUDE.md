## How to work
- Work **subagentically**: parallel Agent subtasks for independent pieces (data vs UI vs save),
  then integrate and test them yourself.
- **Data-driven**: every number goes in `.tres`/CSV under `game/content/data/`. No balance constants in scripts.
- `LoadoutResolver` is the single source of truth for resolved weapon stats, concealment and DR.
  Golden tests go in `game/tests/b/`.
- Skills must **change decisions**. Tier 3–4 skills that are only "+X%" will be rejected by the lead.
- UI must work at 1280×720 to 3840×2160, with keyboard/mouse and gamepad navigation, and every string in the strings table.
- Until ENV A ships `LocalHudModel`, build HUD widgets against a mock model in `game/content/ui/hud/mock/`.

## Session loop
1. `git fetch origin && git merge origin/claude/dreamy-hamilton-pc7vck` (merge, don't rebase).
2. Read new `docs/decisions.md` entries and your latest task message from the lead.
3. Work. Commit small (`[B1-02] loadout resolver`). Push to `env/b-content` only.

5. Update `docs/status/env_b.md` (template: docs/process/communication.md §3), commit, push.
6. Send the lead (`send_message`) `[ENV B] status @ <sha>; check_all: PASS/FAIL; ready: yes/no; questions: QB-n...`.
